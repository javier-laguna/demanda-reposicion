# E10 · Ensayo en limpio

## Objetivo

Comprobar que alguien sin el contexto del desarrollo reproduce la solución siguiendo el README al pie de la letra,
y que el historial no lleve nada sensible.

## Ensayo en limpio

Un clon nuevo del repo en un directorio temporal, sin `.venv`, `data/`, `artifacts/`, `.env` ni cachés. En él se
siguen los pasos del README, sin pasos que no estén escritos.

- **Ruta uv + make:**
  1. `make setup`, `make data DATA_SRC=<zip de la prueba>` y `make pipeline`;
  2. `make validate`;
  3. `make app`, con `/_stcore/health` y las 7 páginas respondiendo;
  4. `make insights` sin key, en modo caché, con los cuatro dominios válidos.
- **Ruta Docker:**
  1. `docker compose build`, la carga de datos con `-v` y `docker compose run --rm pipeline`;
  2. `docker compose up app mcp mlflow`, con los tres servicios respondiendo.
  - El clon de Docker usa sus propios `data/` y `artifacts/`.
- **Qué se compara:**
  - las cifras principales de los dos clones contra las del repo de desarrollo: WAPE por modelo, campeón, costo de
    las políticas, efecto de las promociones y alertas del monitor;
  - entre macOS y Linux, si la caché de insights sigue valiendo con artefactos generados en otra plataforma.
- **Qué se mide:** el tiempo de cada ruta.

## Barrido de seguridad

- gitleaks sobre todo el historial.
- `git log --all --name-only`: ningún CSV, parquet, zip, `.env`, base de datos ni caché de marimo.
- Ninguna ruta local en el historial.
- La imagen de Docker sin `.env`, datos, cachés de marimo ni recibos de archify.

## Criterios de aceptación

- **Las dos rutas terminan** siguiendo solo el README, y las cifras principales coinciden con las del repo de
  desarrollo. En macOS son idénticas; entre plataformas difieren en ~1e-6 relativo.
- **El barrido de seguridad sale limpio.**
- **Si el README pide un paso que falla o falta**, se corrige el README o el código y se repite el ensayo.

## Resultado del ensayo

Hecho el 2026-10-27 sobre el commit `7fd3b48`, con dos clones nuevos en un directorio temporal. Las dos rutas
corrieron a la vez, así que los tiempos están inflados por la competencia por CPU.

- **Ruta uv + make (macOS):** siguió el README sin pasos extra, y terminó.
  - `make setup` y `make data` tardaron segundos.
  - `make pipeline` tardó 32.9 min, de los cuales el backtest fueron 26.4 y la calibración 5.7. `make validate`:
    451 pruebas en verde.
  - **Los 9 artefactos JSON son idénticos byte a byte a los del repo de desarrollo.**
  - `make insights` sin key usó la caché versionada en los cuatro dominios.
  - `make app` respondió en `/_stcore/health` y en las 7 rutas.
- **Ruta Docker (Linux):** siguió el README sin pasos extra, y terminó.
  - `docker compose build` tardó ~2 min con las capas en caché.
  - Los datos se cargaron con `-v`, y `docker compose run --rm pipeline` tardó 40.4 min (backtest 34.9).
  - **Los artefactos que dependen de los modelos difieren en el hash**, como se esperaba por las librerías numéricas
    de Linux. Las cifras principales son idénticas: el WAPE de cada modelo a 4 decimales, el campeón, la conclusión
    del impacto, el efecto de las promociones y su IC, y las alertas del monitor en calibración.
  - **La caché de insights vale entre plataformas:** con artefactos generados en Linux, los cuatro dominios salieron
    de la caché, y `insights.json` es idéntico byte a byte al de macOS.
  - **Servicios:**
    - el tablero respondió en `/_stcore/health`;
    - el MCP por HTTP respondió a `initialize` con el servidor `demanda`;
    - MLflow respondió en `/health`, con `MLFLOW_PORT=5001` porque AirPlay ocupa el 5000.
  - Los runs de MLflow quedaron en `mlflow-docker.db` y `mlruns-docker/`, separados de los de la laptop.
- **Ningún clon quedó con cambios en git** ni con el caché de marimo.
- **Ajuste al README:** los tiempos se actualizaron a lo medido (pipeline ~25–35 min; Docker ~40 min la primera vez).

## Barrido de seguridad

Corrido sobre todo el historial:
- gitleaks sobre todo el historial: sin hallazgos;
- ningún CSV, parquet, zip, `.env`, base de datos ni caché de marimo entró nunca a git;
- ninguna ruta local en los diffs;
- autor y committer de todos los commits con correo noreply;
- la imagen de Docker no lleva `.env`, datos, cachés de marimo ni recibos de archify.
